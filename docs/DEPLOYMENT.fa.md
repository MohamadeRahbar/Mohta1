# انتشار روی mohta1.ir

مسیر انتشار: تغییر و تایید روی لوکال ← کامیت و نسخه GitHub ← نصب همان نسخه روی هاست ← بررسی دامنه و نسخه.

## پیش‌نیاز قابل بررسی

هاست باید Node.js نسخه ۲۴، ماژول داخلی `node:sqlite`، یک فرایند دائمی، HTTPS، فضای نوشتن خصوصی برای SQLite و رسانه، و ارتباط خروجی به پیام‌رسان‌ها داشته باشد. وجود cPanel یا PHP به‌تنهایی این قابلیت‌ها را اثبات نمی‌کند. خوابیدن فرایند در زمان بی‌ترافیکی باعث تاخیر انتشار زمان‌بندی‌شده می‌شود؛ فرایند باید همیشه فعال بماند.

اگر هاست این امکانات را ندارد، فایل‌های Node را در `public_html` قرار ندهید. ابتدا امکان سرویس Node دائمی از میزبان بررسی شود؛ انتخاب بین سرویس مناسب Node یا بازنویسی PHP و زمان‌بند cron پس از مشخص شدن محدودیت واقعی هاست انجام می‌شود. این نسخه به PHP تبدیل نشده است.

## جداسازی کد و اطلاعات

بسته خروجی `npm run package` فقط کد، فایل‌های عمومی و راهنماهاست. برای نصب تازه، اطلاعات محلی منتقل نمی‌شود و حساب و کانال روی دامنه تنظیم می‌شود. برای انتقال اطلاعات واقعی باید پشتیبان کامل داده و کلید رمزگذاری با مقصد و روش انتقال مشخص تهیه شود؛ ارسال صرف دیتابیس کافی نیست.

کد برنامه و `DATA_DIR` را خارج از ریشه عمومی دامنه قرار دهید. فقط فایل‌های `public` می‌توانند عمومی باشند؛ مسیر `/media/` باید همچنان از سرور احراز هویت عبور کند. دیتابیس، فایل کلید، `.env` و نسخه‌های پشتیبان نباید با وب قابل دریافت باشند.

## بسته و بازگشت

GitHub Actions روی شاخه‌ها و تگ‌ها، کد را بررسی، تست‌ها را اجرا و بسته بدون داده تولید می‌کند. بسته و `release.json` را پیش از نصب بررسی کنید. نسخه قبلی را تا تایید نصب نگه دارید. قبل از هر ارتقای داده، از کل `DATA_DIR` پشتیبان سازگار بگیرید؛ بازگشت کد به تنهایی بازگشت ساختار دیتابیس نیست.

نمونه متغیرها در `deploy/production.env.example` است. پورت و دستور شروع باید با مدیر فرایند واقعی هاست هماهنگ شود. `COOKIE_SECURE=true` فقط پشت HTTPS فعال باشد. `/healthz` نسخه فعال را برمی‌گرداند. پس از نصب، ورود، جداسازی برند، نمایش رسانه و زمان‌بند با داده آزمایشی بررسی شود؛ ارسال واقعی آزمایشی به کانال‌ها نیازمند درخواست مشخص است.

## اتصال GitHub به هاست

فعلاً گردش‌کار فقط بسته قابل نصب می‌سازد و به هاست متصل نیست. روش نصب مستقیم به امکانات حساب هاست وابسته است: Git Version Control با deploy hook، یا SSH/SFTP محدود به مسیر همین پروژه. رمز cPanel نباید در مخزن یا فایل workflow ذخیره شود. اگر اتصال نیازمند کلید یا توکن جدید باشد، دسترسی و محدوده آن باید پیش از ایجاد مشخص شود. وضعیت فعال‌سازی و بررسی نصب در گزارش انتشار ثبت می‌شود؛ تولید بسته به معنی دیپلوی موفق نیست.
